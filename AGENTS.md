## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Commands

Use `bunx` instead of `npx` if the project uses bun (`bun.lock` present).

```bash
npx expo install <package>  # ALWAYS use instead of npm/yarn/pnpm/bun add — resolves SDK-compatible versions
npx expo start              # start the dev server
npx expo lint               # lint
npx tsc --noEmit            # typecheck
npx expo-doctor             # diagnose dependency and config issues
```

Run lint and typecheck before declaring any task done.

## Navigation & Routing

- Use **Expo Router** for all navigation. Routes live in `src/app/` — every file there is a screen, `_layout.tsx` files define navigators. Keep non-route code (components, hooks, utils) outside `src/app/`.
- Import `Link`, `router`, and `useLocalSearchParams` from `expo-router`.
- Docs: https://docs.expo.dev/router/introduction.md

## Rules

- If `ios/` and `android/` directories do not exist, they are generated (Continuous Native Generation). Never create or edit them by hand — configure native behavior in `app.json` and config plugins.
- Expo Go only includes its bundled native modules. After adding a library with native code, the app needs a development build: `npx expo run:ios|android` locally, or `eas build --profile development`.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md

## GrimMap project notes

- The map is Leaflet running inside `react-native-webview`. Its source is `src/map/web/map.js` + `map.css`; `npm run build:map` (also run on `postinstall`) inlines them with Leaflet into `src/map/mapHtml.generated.ts`. Rebuild after editing anything in `src/map/web/`.
- RN ↔ WebView protocol: RN calls `window.__tacmap({type, payload})`; the page answers via `ReactNativeWebView.postMessage`. Handlers are listed at the bottom of `map.js`, the RN side is `src/map/TacticalMap.tsx`; the host is `MapFrame.tsx` (WebView) / `MapFrame.web.tsx` (iframe).
- Yandex tiles are EPSG:3395, others EPSG:3857 — switching base layers switches the Leaflet CRS in place. Don't put Yandex tiles in a 3857 map (they'd be offset by hundreds of meters).
- Team sync is Firebase (anonymous auth + Firestore). Data model and access rules: `firestore.rules`. Without `.env` the app runs in solo mode.
- `npm test` runs node:test unit tests in `test/` (pure modules only — no RN imports there).
- `npx expo install` can't reach api.expo.dev from some sandboxes; pin versions from `node_modules/expo/bundledNativeModules.json` instead.
- UI tokens live in `src/ui/theme.ts` (colors `C`, fonts `F`: Exo 2 + JetBrains Mono, radii `R`); reuse `src/ui/components.tsx` (Glass, Sheet, Button, Avatar…) rather than ad-hoc styles. Icons: MaterialCommunityIcons in RN, the same glyphs as `@mdi/js` paths inside the map.
- Security rules tests: `npm run test:rules` (Firestore emulator, needs Java). `.github/workflows/firestore-rules.yml` runs them on every change to the rules and then publishes the rules to Firebase with the `FIREBASE_SERVICE_ACCOUNT` repository secret via `scripts/deploy-rules.mjs` (Rules API directly: the Admin SDK service account can't run `firebase deploy`'s service-usage check) (skipped with a warning when the secret is missing).
- Roles, team colors: `src/lib/roles.ts` (rifle and machine-gun glyphs are custom SVG paths; others are `@mdi/js`). Orders are marker kinds `order-*` (`src/lib/markerKinds.ts`); rules restrict them to the team creator and members with `canCommand`.
- Leaflet marker icons must stay `position: absolute` (Leaflet's own class). Never add `position: relative` to a divIcon className — icons then stack in document flow and drift on zoom.
- `scripts/make-order-sound.mjs` regenerates `assets/sounds/order.wav`.
- Marker level of detail is driven by `lod-dot` / `lod-mid` classes on the map container (`updateLod` in map.js): dots below zoom 15, icons without labels at 15, full detail from 16. Scale inner elements (`.tac-pin`, `.member-pin`), never the Leaflet icon element itself — its `transform` is Leaflet's positioning.
- App display name is GrimMap; `slug` and Android `package` stay `tacmap` on purpose so EAS builds keep the same project and signing key and install as updates.
- Sides (`src/state/side.tsx`, `src/services/sides.ts`): a squad joins a side when its leader writes `{ sideId, sideCode }` into the team doc. Side orders are copies in each targeted squad's `markers` with `audience: 'commanders'` and a shared `groupId`; plain fighters filter them out client-side (not a security boundary). Side-view member/marker ids are `teamId/uid` to stay unique across squads.
- Invite QR/links: `src/lib/invite.ts` (`grimmap://join?team=…|side=…`), scanner `src/app/scan.tsx`, deep-link route `src/app/join.tsx`.
- Marker votes (`staleVotes`/`doneVotes`, threshold in `voteThreshold`), arrows (`kind: 'arrow'` + `points` + `color`, drawn by `setDraw`/`drawChanged` in map.js), chat (`src/services/chat.ts`, client-generated ids so a future Bluetooth relay can dedupe), recordings (`src/services/recordings.ts`; each phone queues its own track points locally (`src/lib/trackBuffer.ts`, AsyncStorage `pendingTracks`) and uploads them in `arrayUnion` batches, so routes walked offline arrive later; the active `recordingId` is cached for offline starts; heatmap via `leaflet.heat`, inlined by build-map-html; samples are resampled by time in `src/lib/tracks.ts`, which bridges gaps up to 10 min (`MAX_GAP_MS`) and keeps lone points, so sparse tracks from pocketed phones still show; replay draws lone points as dots and lists points per player).
- `npm test` uses `scripts/ts-resolve.mjs` so tests can import app modules with extensionless imports.
- Marker deletion follows the chain of command (`src/lib/ranks.ts`, mirrored by `rank()` in firestore.rules): own markers or strictly lower rank.
- Use `KeyboardScroll` (components.tsx) for screens with text inputs; `Sheet` already keeps the focused input above the keyboard.
- Screens: tabs live in `src/app/(tabs)/` (index = map, chat, team = «Отряд», settings) with the custom `src/ui/TabBar.tsx` (bottom in portrait, left column in landscape — the map screen then ignores the bottom/left safe-area insets). Other screens are stack routes in `src/app/`.
- Role badges: `src/lib/roles.ts` builds glyphs with `xf()` (absolute M/L/C/Z paths only) and frames (`roleFrame`); `RoleIcon framed` draws the full badge, without `framed` only the glyph (viewBox `4 4 16 16`, also used for map pins and the self marker).
- Member `status` (`alive`/`dead`/`afk`, `src/lib/status.ts`): set by the fighter or by anyone ranked above them (rules: `rank()` comparison, keys `role`/`status` only). Team `pinned` chat message is written by commanders.
- Coordinate grid: UTM in map.js (`toUtm`/`fromUtm`, `setGrid`), labels kept clear of native panels via `setInsets({ top, bottom })`.
- Map zoom is continuous (`zoomSnap: 0`); never compare `getZoom()` for equality.
- Own point markers are `movable` (not arrows, not side-order copies): long press picks one up (`markerDragStart` → haptic), release posts `markerMoved`; rules let only the author change `lat`/`lng`.
- Side orders are deleted copy by copy (`deleteSideOrder`), never in one batch: each delete runs `rank()` lookups and a multi-squad batch exceeds Firestore's per-request document read limit.
- `Sheet` is a right-side panel in landscape and always has a close button. Inverted `FlatList`s flip their empty component, so render empty states outside the list.
- Offline mesh (Android): local Expo module `modules/grim-mesh` (Kotlin, Google Nearby Connections `P2P_CLUSTER`, autolinked from `./modules`; null on iOS/web/Expo Go). Pure store-and-forward logic in `src/lib/mesh.ts` (envelopes, dedupe, hop limit, latest position per fighter, packing under the 32 KB payload limit; tested in `test/mesh.test.ts`). `src/state/useMesh.ts` runs it inside `SessionProvider`: mesh positions merge into `session.members` (`mergeMeshMembers`), chat goes out over the mesh with the same id as in Firestore, and a phone with internet relays heard messages to the server (`relayedBy`, allowed by rules for squadmates). Markers travel as `mark` envelopes (latest state per marker id, `deleted` tombstones always win) and votes as `vote` envelopes; `mergeMeshMarkers` overlays them on the server list. Marker ids are made on the phone (`newMarkerId`) so both paths share them; heard markers are relayed to the server too (orders only if the author's `rank()` ≥ 2, never side orders). The native code can't be compiled in the cloud sandbox (no Google Maven) — EAS build logs are the compile check.
- Squad writes (markers, votes, profile, status) don't await the server (`background()` in session.tsx): offline the promise only settles on reconnect, which used to freeze dialogs. Refusals still show an Alert when they arrive.
- Offline map areas: `src/lib/tiles.ts` (tile math for EPSG:3857 and Yandex's 3395, verified against Leaflet; URL templates mirror map.js), downloader `src/services/offlineMaps.ts` (tiles under `<documents>/offline/<areaId>/<urlIndex>/<z>/<x>/<y>.<ext>`), state in `OverlaysProvider`. On native the map page is written to `<documents>/map.html` and loaded as a file so `OfflineTileLayer` (map.js) can load tiles from disk first and fall back to the network; areas reach the page via `setOffline`.
- Background mode: `src/services/backgroundLocation.ts` defines the TaskManager task at startup (imported from the root layout) and runs `startLocationUpdatesAsync` with an Android foreground service; fixes go to `useSelfPosition` listeners, so map/Firestore/mesh paths are unchanged.
- Respawn waves: `wave: { every, start }` (ms) on `respawn`/`deadzone` markers, set by commanders (rules: `wave` key only); math in `src/lib/waves.ts` (duplicated as `waveText` in map.js for the on-map countdown badge). Fighters with status `dead` get a buzz a minute before and at each departure.
- iOS / iPad: `supportsTablet`, background location mode; the mesh is Android-only (toggle disabled on iOS). `preview` builds iOS ad hoc for registered devices (`eas device:create`), `preview-ios-simulator` for the simulator.
- Control zone / hot zone (WARDOGS-style): marker kind `hotzone` with `zone: { r, hot, every, start, seed }`, placed and edited by commanders only (rules: `validZone`, `zone` key only; never relayed by the mesh gateway). The hot zone's position is computed from the seed on every phone (`src/lib/hotzone.ts`: hold → warn with the next spot shown → slide); map.js has the same math between `// hz:begin` / `// hz:end`, and `test/hotzone.test.ts` checks the copies agree. UI: `src/ui/ZonePanel.tsx` (marker card, settings) and `ZoneChip` on the map screen; phones buzz when the next spot appears and when the slide starts.
- First launch: `src/ui/RegionPrompt.tsx` offers once (AsyncStorage `regionPrompted`, only with no downloaded areas) to download the current base layer 1–10 km around the first GPS fix (`boundsAround` in tiles.ts).
- `TacticalMap` queues imperative commands (setView, fitPoints…) until the page posts `ready`; the page posts its initial `viewChanged` right after `ready`.
- On web, React Native's `Alert.alert` is a no-op; `src/ui/webAlert.ts` (installed in the root layout) maps it to `window.alert`/`confirm`.
- Android APK without EAS cloud quota: `.github/workflows/android-apk.yml` (manual run) does `eas build --local` on a GitHub runner with the `EXPO_TOKEN` secret (keystore still from Expo) and uploads the APK as an artifact.
- App Store: privacy policy and support pages are `public/privacy.html` / `public/support.html` (published with the web build at f31-exe.github.io/map/); store listing texts in `store/app-store.md`. Settings → «Удалить мои данные» (`deleteMyData` in session.tsx) deletes own messages, tracks (rules allow deleting your own track), avatar, membership and the anonymous account (Apple 5.1.1(v)).
- Big games run by game techs (игротехи) replace the old in-squad faction game (its `factions`/`faction` fields are left unused; `src/lib/game.ts` keeps only the per-minute zone scoring helpers). Data: `games/{g}` (name, ownerId, `techCode`, `sideCode`, `tickets`, `match {start, minutes, stoppedAt}`, `tiebreak`), `gameCodes/{code}` → `{gameId, kind: tech|side}`, subcollections `techs/{uid}` (being a tech = this doc exists; the creator or anyone with the tech code adds themselves, any tech removes), `sides/{sideId}` (name, color, ticket bonus), `players/{uid}` (self-registered, rules check squad → side → game; `pts`, `deaths`, `cell`/`cellAt`), `markers/{id}` (game markers: `hotzone`, `flag`, `sector`, `ball`; techs write, players may only capture flags). Side docs get `gameId`/`gameCode` (attached by the side commander with the side code, or created by a tech with a one-time `claim` code). Techs read every side's squads, members and markers (`oversees()` in rules). State: `src/state/game.tsx` (GameProvider inside SideProvider), services `src/services/games.ts`, screen `src/app/game.tsx` (link card `GameLinkCard` in the team tab and side screen). Techs are orange diamonds (`TECH_COLOR`, `Member.tech`, `.tech` classes in map.css); techs see commanders of every side, or every fighter with «Все бойцы». Pure mode logic in `src/lib/gameModes.ts` (tested in `test/gameModes.test.ts`): match clock; territories (3×3 sectors numbered like the snail; players report their sector mid-minute, side with more fighters for `CAPTURE_MINUTES` in a row takes it, tie pauses, result with draw/time tiebreak); flags (held minutes from the capture `log`); tickets (start + bonus − deaths); WARDOGS zone points; football (`ball {progress, at, push, goal}` along the side's arrow `points`, `ballPush`: owners alone forward ×n, opponents alone back ×n/2, mixed never back, `BALL_SPEED` m/min per fighter, `BALL_RADIUS` 10 m; a goal stops the match, otherwise the larger share of the arrow wins). Territories and football are refereed by one online tech phone (smallest uid among techs seen in the last 3 min): territory one finished minute per pass, balls every 3 s from the members' live positions. Balls are drawn from the draw bar («Мяч», techs only); map.js `buildBall`.
- map.js: don't redraw vector layers during a zoom animation (`zooming` flag) — they get drawn at the wrong place and jump. Messages in `DEFER_WHILE_ZOOMING` (setSelf, setMarkers, setMortar, setNav, setTrail, setAnalysis) wait for the zoom to settle (latest payload per type); the grid redraws after it.
- Mortar (role `mortar`): calculator math in `src/lib/mortar.ts` (tested in `test/mortar.test.ts`): high-angle drag-free model with the max range at 45° (θ = 90° − ½·asin(d/R), 45°–85°), or linear interpolation over the crew's test shots (`table`, ≥2 shots); azimuth also in 6000-division mils. Config and an optional fixed firing position live in AsyncStorage (`src/state/useMortar.ts`); the range is published as `range` on the member doc (rules: number 0–2000) so everyone draws the circle. UI: a round «Миномёт» button in the bottom-right action column for mortar crews, `src/ui/MortarPanel.tsx` replaces the bottom HUD (target = crosshair, spotter corrections pan the map via `correct()`), «Навести миномёт» in marker cards. map.js `setMortar` draws range circles and the live line of fire to the map center; your own circle and firing position show only while the calculator is open (others' circles always).
- Own heading (compass, `useSelfPosition().heading`) is shown as «Курс» in the bottom HUD, as «Мой курс»/«Повернуть» in marker and member cards, and in the mortar panel; `turnText`/`turnAngle` in `src/lib/heading.ts`.
- Meshtastic (LoRa radios, e.g. Heltec V3 (ESP32) and Heltec T114 (nRF52840)), Android and iOS: BLE via `react-native-ble-plx` (config plugin in app.json, iOS `bluetooth-central`; not in Expo Go/web — `radioSupported`). Protocol in `src/lib/meshtastic.ts` (hand-rolled protobuf in `src/lib/protobuf.ts`; field numbers and BLE UUIDs checked against `@meshtastic/protobufs` 2.7 and `@meshtastic/transport-web-bluetooth`), link in `src/services/meshRadio.ts` (want_config handshake, FromNum notify → drain FromRadio, queued ToRadio writes, heartbeat), connection state in `src/state/useRadio.ts` (remembered device `KEYS.radio`, auto-reconnect, heard-radio list). It is a second transport inside `useMesh`: envelopes go out on PRIVATE_APP (256) in the squad channel (slot 1, secondary, AES-256 key = sha256 of the team id, set by an admin message — automatically when the slot is free, with confirmation otherwise) and land in the same `MeshStore`. `src/lib/lora.ts`: compact binary positions (one packet), JSON for chat/marks/votes, fragments of ≤233 bytes (`Reassembler`), fragment size per link from the negotiated Bluetooth MTU (`payloadForMtu`: a ToRadio write must fit one ATT packet — 512 on ESP32, 247 on nRF52 boards, ~185 on iPhones; `TO_RADIO_OVERHEAD` checked in tests), `RadioOutbox` pacing (2.5 s between packets, chat/marks before positions, latest position per fighter). Own position on air when moved 15 m, at a pace that scales with the squad radios heard in the last 10 min (`radioPosIntervals`: ≥30 s, ~n×7.5 s so all-moving positions take ≈25 % of LongFast airtime; standing still and Nearby relays 3× rarer). Radio-heard envelopes are passed on to Nearby peers but never re-sent on air (radios flood by themselves). Tested in `test/lora.test.ts`; the BLE link itself can only be checked on a device.
- Map rotation: `leaflet-rotate` (inlined by build-map-html right after Leaflet): two-finger twist / Shift+wheel, `setBearing` / `setHeadingUp` handlers, `bearingChanged` / `headingUpChanged` posts. Icons stay upright, so heading cones/arrows are drawn at heading + bearing (`bearing()` in map.js); grid edge labels are placed in screen pixels (`edgePoint`) so they work at any bearing. The toolbar compass: rotated → north-up; north-up → heading-up (follows the compass, centered on self); turning by hand ends heading-up. Pinch-zoom doesn't turn the map: map.js wraps leaflet-rotate's `touchGestures` so turning starts only after an 18° twist (`TWIST_DEG`) and never in a pinch that already zoomed.
- Grid modes (`session.gridMode`: off / utm / snail; `KEYS.grid`, old `true` = utm). Snail grid («улитка»): 500 m UTM-aligned squares named letter (east) + number (south) from the NW corner of А1, each split 3×3 in a spiral 1 2 3 / 8 9 4 / 7 6 5 and again; math between `// snail:begin` / `// snail:end` in map.js (tested in `test/snail.test.ts`). Origin: team doc `grid: {lat,lng}` set by commanders (rules `validGrid`), local `KEYS.gridOrigin` when solo, else squares count from 5 km UTM blocks. The crosshair's square comes back in `viewChanged.snail` («Б3-7-4») for the HUD. UI: `src/ui/GridSheet.tsx`, chips in settings.
- Side commander's map shows one mark per other squad (its commander, or the freshest member with command rights) labelled with the squad name (`Member.mapLabel`), unless «Все бойцы» is on.
- Night mode (`src/state/night.ts`, `KEYS.night`; toggled in settings only): `src/ui/NightFilter.tsx` multiplies the screen by deep red (`mixBlendMode: 'multiply'`) — rendered last in the root layout and inside every `Sheet` panel (never full-window inside a transparent Modal: it would paint the app red); on web a CSS filter on the document. The map page gets `setNight` (CSS filter on `#map`).
- Zones with alerts: marker kinds `area-dead` / `area-enemy` / `area-bound` with `points` (polygon, ≥3) drawn from the draw bar's kind chips; map.js `buildArea`. `src/lib/geofence.ts` `ZoneWatcher` (tested): alert after two agreeing fixes, fixes worse than 35 m ignored; entering dead/enemy zones and leaving the boundary buzz twice and show the top banner for 10 s.
- «Вести сюда» (marker and member cards): `nav` state on the map screen, `src/ui/NavPanel.tsx` replaces the HUD (arrow = turn relative to compass, or map direction without one), ETA from `SpeedTracker` (`src/lib/nav.ts`, walking pace 1.25 m/s when still), buzz on arrival (≤15 m); map.js `setNav` draws the line. With the calculator or nav panel open, or when the bottom-right column would reach the toolbar (`columnHitsToolbar`, height counted from the button count), the action buttons form a row.
- Own trail: `src/lib/trail.ts` (crumb every 5 m, last hour kept, `KEYS.trail`), minutes shown `KEYS.trailMinutes` (settings chips), map.js `setTrail`.
- Photo markers: kind `photo` with `photoId` + `heading`; picture (`src/services/photo.ts`, JPEG ≤ 380 K chars) in `teams/{id}/photos/{photoId}` (rules: author creates, author or superior deletes); personal ones keep `photoData` inside the marker. Mesh/radio carry the marker only. Map shows a wedge toward `heading` (`.tac-dir`, adjusted for bearing). Camera button in the action column; `src/ui/PhotoView.tsx` in the card.
- Squad maps: `src/services/sharedMaps.ts` — `teams/{id}/maps/{mapId}` meta + `parts/{nn}` base64 chunks (≤700 K chars each, file ≤4.5 MB), parts written first. `OverlaysProvider` subscribes and downloads new ones automatically (native only), `OverlayMeta.sharedId` links files to squad maps; removing one locally adds it to `KEYS.sharedMapsDismissed`. Share/unshare buttons on the maps screen; rules: members share as themselves, author or superior removes.
- Offline schematic regions (like 2GIS): `.github/workflows/offline-regions.yml` extracts each Russian region (`scripts/regions/regions.mjs`, bbox from Nominatim with 0.15° margin, fixed boxes for Chukotka/Crimea/Sevastopol) from the newest Protomaps planet build (`pmtiles extract`, maxzoom 15, OpenStreetMap vector data) and publishes `<id>.pmtiles` + `<id>.json` and the merged `regions.json` on the release `offline-regions` (runs monthly from the default branch, by hand, and on changes to the builder). App: `src/services/vectorRegions.ts` (index, resumable `DownloadTask` to `<documents>/regions/<id>.pmtiles`, `readRange`), state `src/state/regions.tsx` (`RegionsProvider`, `KEYS.vectorRegions`), screen `src/app/regions.tsx` (linked from the offline sheet and the layer picker). Map: base layer `offline-scheme` (EPSG:3857) draws one `protomapsL.leafletLayer` (flavor light, lang ru, bounded by the region bbox) per region; protomaps-leaflet and pmtiles are inlined by build-map-html. The page can't read byte ranges of local files, so its PMTiles source posts `pmRead {k,id,offset,length}` and `TacticalMap` answers `pmData {k,b64}` from an open `FileHandle`.
- Desktop / laptop = the web version as an installable app (PWA) in Chrome or Edge: `public/manifest.webmanifest`, `public/icons/`, `public/sw.js` (app shell cached; navigations network-first with the cached page offline; same-origin assets cache-first; the page posts the resources it loaded before the worker took over), registered by `src/services/pwa.web.ts` (`setupPwa()` in the root layout, not on localhost). Meshtastic in the browser: `src/services/meshRadio.web.ts` — Web Bluetooth (same GATT service) and Web Serial over USB (frames 0x94 0xC3 + length, `src/lib/serialFrames.ts`, tested), chosen with `pickRadio` from a click (RadioCard «Bluetooth» / «USB-кабель»), reconnect via `getDevices()` / `getPorts()`. The protocol session (handshake, write queue, heartbeat, FromRadio handling) is shared by all transports: `src/services/radioSession.ts`. Offline schemes in the browser: `src/services/vectorRegions.web.ts` — release files can't be fetched by a page (no CORS), so «Скачать» downloads the .pmtiles normally and «Добавить скачанный файл» copies it into OPFS; the region list is copied next to the app by web.yml (`dist/regions.json`). Without GPS (laptops) the map uses the connected radio's own GPS position (`radio.myPosition`).
- Over-the-air updates (EAS Update): `expo-updates`, `runtimeVersion: { policy: 'fingerprint' }` and `updates.url` in app.json, build profiles on channels `preview` / `production` (eas.json). Publish: APK workflow target `update` (`eas update --channel preview --platform android`; the build profile's env doesn't apply to updates, so the workflow sets the public Firebase config itself). An update reaches only builds with the same native fingerprint — adding a native module needs a new build. Settings: `src/ui/UpdatesCard.tsx` (running update, check, restart into a downloaded one).
- Battery: `src/hooks/usePhoneBattery.ts` (expo-battery; the Battery API in browsers) and the radio's DeviceMetrics battery (`decodeTelemetryBattery`, NodeInfo field 6; `radio.myBattery`) ride along with positions on the member doc (`battery`, `charging`, `radioBattery`; rules in `validProfile`). `src/lib/power.ts` (`lowPower` < 20 %, `powerText`; tested): member card text, orange `.member-low` badge on map pins.
- HQ on wide screens (≥ 1000 px, toggle «Штаб» in the toolbar, `KEYS.hq`): `src/ui/HqPanel.tsx` beside the map — squads with each fighter's status, link age and battery (techs: every side from `game.roster`; side commanders: `side.squads`; others: own squad) and an event feed: deaths/afk/back and low battery seen while open, plus orders and enemy marks (last 2 h), flag/territory captures (from `log`) and goals from the markers. Tapping a row or event centers the map there.
